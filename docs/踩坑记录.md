# 踩坑记录（按实际报错倒推）

这份是「真跑一遍之后才知道」的东西。README 讲怎么用，这里讲**报错长什么样、根子在哪、怎么改的**。
以后再编新内核版本，先扫一眼这张表，能省掉一晚上。

版本信息：首次跑于 2026-11，目标内核 `6.18.54`，机器 `ubuntu-24.04-arm`。

## 坑 1：只编 modules，modpost 全线 undefined

**报错（节选）**

```
MODPOST modules-only.symvers
WARNING: vmlinux.o is missing.
         Modules may not have dependencies or modversions.
         You may get many unresolved symbol errors.
ERROR: modpost: "register_pernet_subsys" [fs/nfs_common/grace.ko] undefined!
ERROR: modpost: "__register_nls" [fs/nls/nls_cp857.ko] undefined!
WARNING: modpost: suppressed 8745 unresolved symbol warnings because there were too many)
make[2]: *** [scripts/Makefile.modpost:147: modules-only.symvers] Error 1
```

**根子**：`make modules` 在没编过 `vmlinux` 的树上做 modpost，拿不到 `vmlinux.o`，
于是内核自己导出的符号（`register_pernet_subsys`、`init_net`、`_ctype`…）全被判成未定义。

**改法**：造 kit 阶段直接**整编**（vmlinux + modules），编完强校验两样东西必须存在：

```sh
make -C "$SRC" ARCH=arm64 -j"$JOBS"
[ -f "$SRC/vmlinux" ] || die "整编完了却没有 vmlinux"
[ -f "$SRC/Module.symvers" ] || die "整编完了却没有 Module.symvers"
```

> 代价：整编比只编 modules 慢（本机约 9 分钟 / 4 核 arm），也是磁盘大头。

## 坑 2：kit 里没放内核 `sound/` 源码树，`snd-soc-core.o` 找不到

**报错**

```
make[3]: *** No rule to make target 'snd-soc-core.o', needed by './'.  Stop.
make[2]: *** [.../build/Makefile:2050: .] Error 2
build-modules: sound 编不过
```

**根子**：音频栈的 `sound/Kbuild` 本身不带源码，它引的是内核源码树里的文件：

```make
snd-soc-core-y := $(patsubst %.c,soc/%.o,$(filter-out $(soc-skip),$(notdir $(wildcard $(src)/soc/soc-*.c))))
snd-compress-y := core/compress_offload.o
snd-aloop-y    := drivers/aloop.o
snd-dummy-y    := drivers/dummy.o
```

我们只建了空的 `ext/sound/`，`$(src)/soc/` 是空的，于是 `snd-soc-core.o` 没有规则。

**改法**：从内核源码树补齐三个子目录（**别拷顶层 `Kbuild` / `Makefile`**，拷了会把上游规则顶掉）：

```sh
for d in soc core drivers; do cp -a "$KIT/build/sound/$d" "$KIT/ext/sound/"; done
```

## 坑 3：兄弟模块的 `Module.symvers` 没先编出来（还没炸但一定会炸）

**症状**：编到 `sprd_audio` 时 `Unknown symbol ...`。上游链接时用的是：

```
KBUILD_EXTRA_SYMBOLS="$mb/sprd_modem/Module.symvers $mb/sound/Module.symvers"
```

`sound` 我们自己编了，但 `sprd_modem` 的符号表是**编出来的**，仓库里不带。
原来那句 `cp .../Module.symvers ... || true` 会把缺失吞掉，问题拖到后面才现形。

**改法**：kit 阶段先编一次 `sprd_modem`，把符号和头文件一起进 kit，且**拷不到就失败**：

```sh
cp -r "$MU300"/upstream/modules/sprd_modem "$VMOD/sprd_modem"
make -C "$SRC" ARCH=arm64 M="$VMOD/sprd_modem" -j"$JOBS" modules
cp -a "$VMOD"/sprd_modem/Module.symvers "$KIT/ext/sprd_modem/Module.symvers" || die "sprd_modem 没产出 Module.symvers"
```

## 顺手记下的环境事儿

| 事 | 结论 |
|---|---|
| runner 磁盘 | 整编一次 6~8G，十几 G 的盘复制一份就爆。自己下的源码树用 `mv` 进 kit，别 `cp` |
| 触发方式 | `workflow_dispatch` 面板有时被上次报错弹层挡住（`BU_TARGET_OBSCURED`），改为推 tag：`git tag -f k-<KREL> && git push -f origin k-<KREL>`，配 `on: push: tags: ['k-*']` |
| 看失败原因 | Actions 的 step 日志是虚拟化列表，页面文本只拿得到几百字。用右上角 **Explain error**（Copilot 会把关键几行贴出来），比翻日志快 |
| 源码校验 | 只认 kernel.org 的 `sha256sums.asc`：`linux-6.18.54.tar.xz` = `9df30b02dd8102bbd0be52556288ef6889ddbe7f1ddb96fbf847d0becf3eacac` |
| 配置校验 | `config/<KREL>.config` 必须是设备 `/proc/config.gz` 原件，sha256 记在 `kits.lock`，变了就 die |

## 判据（什么时候算真成了）

```
== 校验 6.18.54：清单 25 个，缺 0，问题 0
```

三连缺一不可：数量齐、每个 `.ko` 的 `vermagic` = KREL、上游每个补丁在二进制里留下标记字符串。
真机再加一层：装上后 `/etc/airsim/no-audio` 自动消失，`ubus call airsim status` 的 `audio_available` 变 `true`。

## 4. `git add` 没报错，远端却找不到文件

**报错原文**：无报错。`git push` 返回 0，`git show --stat` 只列出 `README.md` 和 `SHA256SUMS`，`raw.githubusercontent.com` 取包 404。

**根子**：`.gitignore` 里有 `*.tar.gz`、`*.ko`、`out/`——这些是为「编译产物不污染仓库」写的，结果把 `archive/` 下**唯一来源的冷存档包**一起吃掉。`git add` 对已忽略文件是静默跳过，不提示。

**改法**：
1. 在 `.gitignore` 末尾加例外，顺序要在忽略规则**之后**：
```
# 冷存档例外：这些 tar.gz 是唯一来源，必须进 git
!archive/**/*.tar.gz
```
2. `git add -f archive/...` 强制加入
3. 推完别信 `git push` 的返回码，用远端核对：
```
curl -s "https://api.github.com/repos/<o>/<r>/contents/<dir>?ref=main"
```
看文件名和 `size` 对不对——`git ls-remote` 只能证明 commit 到了，证明不了文件在里面。

**判据**：`git show --stat HEAD` 的 `Bin 0 -> N bytes` 行才代表二进制真进了提交。
