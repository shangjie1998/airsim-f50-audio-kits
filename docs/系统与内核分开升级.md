# 系统与内核分开升级（F50 / mu300）

这台设备把「操作系统」和「内核」切成两块单独升级，弄明白这块，就不会再出现「升个系统，音频没了」。

## 两块东西在哪

| 块 | 位置 | 谁管 |
|---|---|---|
| OS 根文件系统 | `/mnt/mu300-disk/openwrt`（A/B 双槽） | `mu300-update apply openwrt` |
| boot 槽（内核 `Image` + ramdisk + vbmeta） | `/mnt/mu300-disk/boot` | `mu300-update kernel 6.18` / `boot` |
| 数据盘（存档、音频件、备份） | `/mnt/mu300-disk/extra` | 升级不碰 |

## 命令对照

```
mu300-update check                     # 装了啥、最新是啥
mu300-update apply openwrt             # 换系统根fs（注意：会顺带换 boot image，也就是内核）
mu300-update boot                      # 只换 boot image（连内核）
mu300-update kernel 6.18               # 只换内核，OpenWrt 根系统不动
mu300-update rollback openwrt          # 退回旧系统
mu300-update rollback-boot             # 退回旧内核
mu300-update clean                     # 删掉保留的 <os>.old
```

**关键一条**：`apply` 会连 boot image 一起换。所以「系统升级完，内核版本变了」是设计如此，不是出错。

## 升级会保留什么（脚本里写死的清单）

`apply` 时先搬出来、装完再搬回去：

- `etc/config`（**所有 UCI 配置，插件设置都在这**）
- `etc/mu300`、`etc/unisoc-modem`（APN/模组配置）
- `etc/dropbear`（SSH 密钥）、`rc.local`、`crontabs`、`root`
- `opt/mu300/android`、`lib/firmware`（如 `agdsp.bin`）、**`lib/modules`**

所以：插件配置不丢、开机脚本不丢、**旧内核的模块树也不丢**（`/lib/modules/6.18.60` 就是这么留下来的）。

会丢的：自己装的 apk 包——除非用 `--no-reinstall`，或者 `MU300_KEEP_PACKAGES=0` 让它重启后重装。

## 标准流程（每次上游发新版）

```sh
# 0) 升级前先记一笔，别等出事才翻
uname -r; ls /lib/modules; cat /mnt/mu300-disk/boot/installed.id

# 1) 看有没有新版
mu300-update check

# 2) 换系统
mu300-update apply openwrt

# 3) 升完看内核变成什么了
uname -r

# 4) 判断新内核有没有声音子系统
ls /lib/modules/$(uname -r) | grep -c '^snd'        # 0 = 这版没声音
zcat /proc/config.gz | grep -c '^CONFIG_SND'         # 0 = 配置里没开

# 5) 没声音就把内核钉回有声音的那版（离线，不花流量）
#    必须同时给 MU300_RELEASE！脚本里 t=${MU300_RELEASE:-$(latest_release)}，
#    只给本地包它照样会先去联网查版本号，断网时报 could not reach GitHub
MU300_RELEASE=v2026.11.02.1 \
MU300_KERNEL_BUNDLE=/mnt/mu300-disk/extra/upstream-archive/mu300-kernel-6.18.tar.gz \
  mu300-update kernel 6.18
# 装成功的标志：日志里同时出现
#   boot: 2956 modules for 6.18.60 installed
#   boot: updated to v2026.11.02.1

# 6) 重启（换内核必须重启才生效）
```

## 判断内核能不能跑音频的三条判据

1. `/lib/modules/<release>/` 里有 `snd-pcm.ko`、`snd-timer.ko` → 有 ALSA 核心
2. `/proc/kallsyms` 里有 `snd_pcm_new`、`snd_card_register` → 符号导出到内核
3. `/proc/config.gz` 里 `CONFIG_SND` 系列不是 `# CONFIG_SOUND is not set`

三条里任何一条不过，**音频模块一个都装不上**，这时别重编模块，直接换内核（原因见下）。

## 踩过的坑

### 1. 内核没声音子系统，重编模块一定失败
6.18.54 那版：`# CONFIG_SOUND is not set`、`snd*` 模块 0 个、`snd_pcm_new` 0 个符号。
按设备配置重编 25 个音频模块，modpost 会报一堆 `undefined`——因为要挂的「架子」根本不存在。
**判据**：先查上面三条，再决定要不要编。

### 2. `.gitignore` 会静默吃掉存档包
`*.tar.gz` 这类「产物不入库」规则，会把 `archive/` 下唯一来源的包一起忽略；`git add` 不报错、`git push` 返回 0，但远端是空的。
**改法**：`.gitignore` 末尾加 `!archive/**/*.tar.gz`；推完用 `contents` API 核文件大小，别信返回码。

### 3. 升级后要重装/重配自己的插件包
上游 `apply` 不会管你的插件；而且我们自己的插件包里有默认 `etc/config/airsim`（`enabled='0'`），装的时候会盖掉设备配置——装完要回拷旧配置。

### 4. 流量紧时只有内核能离线装
`MU300_KERNEL_BUNDLE=<本地 mu300-kernel-<ver>.tar.gz>` 是内核的离线口子，**但必须配 `MU300_RELEASE=<tag>` 一起给**（只给包、不给 tag，脚本仍会去 `latest_release` 联网查版本，断网必失败）；OS 根fs 没有等价开关，必须联网下。

## 存档在哪

`archive/6.18.60/`：
- `airsim-audio-6.18.60.tar.gz` — 设备上跑通的 25 个音频 `.ko` + `KERNEL` + 补丁 + ABI 报告
- `upstream/mu300-kernel-6.18.tar.gz` — 上游 v2026.11.02.1 的 6.18 内核原包（`kernel.release=6.18.60`，2956 个 `.ko`，`Image` 内含 `Linux version 6.18.60`）
- `SHA256SUMS`

## 一句话记住

> 升完系统先别急着装音频，先看 `uname -r` 那版有没有 `snd`；没有就把内核钉回 6.18.60。
